## 2026-04-09: 未测试就推送代码

### 错误行为
修改了 `functions/yahoo-finance-proxy.ts` 的数据过滤逻辑后，没有进行测试就直接 commit 和 push 到生产环境。

### 用户纠正
"你测试过了吗？你以后都要测试了之后没问题再推送"

### 为什么这是错误的
1. **风险高**：未经测试的代码可能引入新的 bug
2. **不专业**：专业的开发流程应该是：修改 → 测试 → 确认 → 推送
3. **浪费时间**：如果代码有问题，需要再次修复和部署，增加了迭代成本
4. **影响用户**：可能导致生产环境出现问题，影响用户体验

### 正确的做法
1. **修改代码**
2. **本地测试**：运行测试脚本或手动测试修改的功能
3. **验证结果**：确认修复有效且没有引入新问题
4. **推送代码**：只有在确认无误后才推送

### 测试方法
对于这次修改，应该：
```bash
# 1. 测试修改后的 function（本地或通过 Cloudflare）
node test-nasdaq-price-data.cjs

# 2. 验证数据过滤逻辑是否正确
# 3. 确认没有引入新的问题
# 4. 然后才 git push
```

### 今后必须遵守的规则
⚠️ **永远不要在未测试的情况下推送代码到生产环境**
- 每次修改后必须先测试
- 测试通过后才能 commit 和 push
- 如果无法本地测试，至少要仔细 review 代码逻辑


## 2026-04-09: 错误诊断 - Yahoo Finance 数据源问题

### 问题重新分析
用户指出：今天是4月9日，4月8日（周三）是交易日，应该有数据。如果数据源没有数据，说明数据源本身有问题。

### 验证结果
1. **AP News 确认**：4月8日市场确实开市，Nasdaq Composite 上涨 2.8% 至 22,635.00
2. **Yahoo Finance API 问题**：多次测试显示 Yahoo Finance 返回4月8日的时间戳，但 close 值为 `null`
3. **数据源可靠性**：Yahoo Finance 对于 Nasdaq 100 (^NDX) 的数据更新存在延迟或问题

### 错误的假设
之前我假设"API 返回 null 是正常的，只需要过滤掉"。但实际上：
- 4月8日是交易日，应该有数据
- 数据源返回 null 说明数据源本身有问题
- 应该寻找更可靠的数据源，而不是简单过滤

### 正确的解决方案
需要：
1. 寻找更可靠的 Nasdaq 100 数据源
2. 实现数据源降级策略（主数据源失败时切换到备用数据源）
3. 不能简单地过滤掉 null 值，而应该主动获取正确的数据

### 学到的经验
- **不要盲目信任单一数据源**：即使是 Yahoo Finance 这样的大型数据源也可能有延迟或问题
- **验证业务逻辑**：交易日应该有数据，如果没有，说明数据源有问题，不是数据本身的问题
- **实现降级策略**：关键数据应该有多个数据源作为备份


## 2026-04-09: 错误的数据源选择 - QQQ vs NDX

### 用户纠正
"你的数据好像有点不对啊，我要的是纳斯达克100的指数价格，昨天已经到了25000附近了"

### 错误
我使用了 QQQ (Nasdaq 100 ETF) 的价格（约 $606）来代替 Nasdaq 100 指数 (NDX) 的价格（约 24,000-25,000）。

### 问题
1. **QQQ 是 ETF，不是指数**：QQQ 的价格约为指数的 1/40
2. **Alpha Vantage 免费版限制**：不支持指数数据（^NDX, NDX 等都无法获取）
3. **数据不匹配**：用户需要的是指数价格，不是 ETF 价格

### 验证
- QQQ (ETF): $606.09 (4月8日)
- NDX (指数): 应该在 24,000-25,000 左右
- 比例: NDX ≈ QQQ × 40

### 正确的解决方案
1. **继续使用 Yahoo Finance**：虽然有数据延迟，但它支持指数数据
2. **处理 null 值**：当遇到 null 时，可以：
   - 显示"数据更新中"
   - 使用前一交易日数据
   - 添加数据时效性说明
3. **不要用 ETF 代替指数**：这会导致数据完全错误

### 学到的经验
- **理解数据类型的区别**：指数 vs ETF vs 股票
- **验证数据合理性**：24,000 vs 600 的差异应该立即引起警觉
- **API 限制调研**：Alpha Vantage 免费版不支持指数，这是关键限制
- **不要为了"有数据"而使用错误的数据**：没有数据比错误数据更好
